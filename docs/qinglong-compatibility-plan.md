## 1. 需求与确定决策

| 用户要求 | 首版交付决策 |
| --- | --- |
| Actions 与青龙独立执行/记录 | 两个入口，不共享配置、状态、日志、锁或监控项；只复用库代码 |
| 一键导入 | 必做；填写配置及授权后，一条命令自动创建/同步全部项目任务 |
| 成功通知/失败通知 | 两个独立开关，默认均开启；可只成功、只失败、均发或均不发 |
| 集合/分别通知 | 独立于成功/失败开关；默认分别，同时间计划可集合，不同时间分开 |
| 自定义时间 | 默认青龙当地时间 00:30、08:30；每任务可以覆盖 |
| 多任务配置在一个文件 | 带前缀分节和中文注释的 TOML 模板；密钥可直接填或显式引用变量 |
| 必要结果信息 | 青龙专用中文通知，任务、账号别名、结果、收益（可取得时）、原因、时间、耗时、运行编号 |
| 日志及自动清理 | 自有脱敏日志按时间/容量清理，不删除其他青龙任务日志 |
| 先修原版再开发 | P0 独立修正、验证、提交并记录 SHA 后，才能开始青龙功能代码 |

本版替代旧计划的“首版手动建任务”“失败通知后续再做”“青龙沿用 09:00/14:00”。

## 2. 两个入口的兼容边界

~~~text
Actions / 原本地 CLI → 原入口、原配置、原状态、原通知
青龙                → 青龙入口、TOML 配置、青龙状态、青龙通知
                       两者仅复用签到解析、HTTP、安全及传输库代码
~~~

- 原入口 python -m checkin_tools 保留；新入口 python -m checkin_tools.qinglong，不改原 CLI 主执行路径。
- 原参数、.env 自动加载、环境变量优先级、退出码、state v2、通知默认值和格式保持不变。
- 原签到 workflow 保持北京时间 09:00/14:00、无应用层随机延迟；不迁移到新入口。
- 青龙 local 00:30/08:30 不影响 Actions；不自动操作 GitHub Secrets、Cache、工作流或原本地配置。
- 原环境变量不会隐式进入青龙；只有集中配置明确引用时才读取。
- 两端可分别启用或同时存在。同一账号两边执行可能重复请求/通知，这是边界，不做跨端去重。
- 不设计主备、接管、共享锁、结果互认。安装青龙不以关闭 Actions 为先决条件。
- 共享代码增加字段须兼容旧构造与格式；青龙平台依赖隔离，旧 Windows/Linux/macOS 入口不依赖青龙。

## 5. 集中配置规范

- 采用 TOML、Python 标准库解析，不 source/eval，不把配置作为程序执行。
- 一份文件组织 runtime、schedule、notify、logs、qinglong、tasks 等前缀节，模板完整示例见教程。
- 每任务有稳定 id、site、enabled、可选 cron、通知覆盖和 accounts 列表；每账号有稳定 id 与脱敏 label。
- 排序/改显示名不影响 ID；更换账号身份必须更换 ID 或显式重置该账号状态。
- 校验安全 ID、重复 ID、未知字段/站点、cron、启用任务缺少账号、通知渠道缺失/不完整等。
- 默认值 → 文件全局 → 任务明确覆盖；路径优先级 --config > CTQL_CONFIG > 默认绝对路径。
- 密钥字面量与 *_env 引用互斥，连空字面量也需删除后才能改用引用；建议变量前缀 CTQL_。
- 无 .env 或 Actions 变量隐式回退；明确引用旧多账号变量时不能误当成单账号 Cookie。
- 关闭的任务允许保留空示例，启用的任务必须完整；错误仅打印字段名和脱敏原因。
- 一次运行读取完整配置快照，不在多任务间反复覆盖全局环境变量。
- 青龙独立适配器组装共享 Checker 配置；不调用旧 load_config 去读取整个系统环境。

## 6. 调度与一键导入（首版必做）

### 6.1 自定义时间

- 全局默认 cron = "30 0,8 * * *"，当地每天 00:30/08:30；每任务可覆盖。
- timezone = "local" 指青龙实际调度时区，不是浏览器、助手或未经确认的宿主机时区。
- 导入显示具体 IANA 时区及下次执行预览；无法可靠解析时要求填明确时区，不静默降到 UTC。
- 配置时区须匹配目标青龙调度时区；不擅自修改整个实例时区，不作未经验证的时区 cron 换算。
- 正式支持的 5/6 字段语法、DST 跳过/重复行为须实测记录。
- 调度日与服务日分开：V2EX 按现有 UTC 日；其他当前站点沿用原业务日期。
  北京时间 00:30 与 08:30 的 V2EX 属不同 UTC 日，不能错误去重。

### 6.2 一键的定义

完整仓库安装、配置和一次性应用授权完成后，manage.sh import-tasks 自动创建/同步全部启用任务及维护任务。
支持 --dry-run 预览、--yes 一次应用；不要求用户逐项复制名称/命令/cron，手动建任务只作排障后备。

通过[青龙应用授权](https://qinglong.online/api/preparation)和[公开任务 API](https://qinglong.online/api/crontab)实现，
不直接写数据库或提取内部管理员密钥。具体版本和字段需实测；“一键”不意味着绕过授权。
权限仅开放需要的定时任务模块，日常签到不需要管理 API 凭据。
本机回环可 HTTP，远程必须 HTTPS；禁止跨主机重定向带走密钥，认证查询参数及异常须脱敏。

原生订阅可后续补充，但本次一键导入不能延期。不得把只复制单脚本的订阅当作 src-layout 包安装。

### 6.3 幂等与保护

- namespace + 稳定任务/组 ID + 自有清单确认归属，不仅按显示名匹配。
- 重复导入不重复创建；重命名保留映射；移除配置项默认禁用受管任务，不删除日志。
- 其他青龙任务不动，同名非受管对象报冲突。
- 首次业务任务默认禁用，验证后 --enable 一键启用；该标志明确授权定时运行。
- 更新保留原启用状态；分组/调度变动时暂停相关任务、等执行结束，再切换清单，防止旧新两套运行。
- 文件为唯一任务配置源；面板手改先展示冲突，不静默覆盖。
- 保存旧命令/cron/启用状态供回滚；API 无批量事务保证，失败逐项回滚或保持禁用并列明未恢复项。
- 网络结果不确定先重查，不盲重试创建；写完回读核对。
- 命令只含安全校验/转义后的路径、ID、受管版本，不含密钥和任意配置代码。
- 调度/分组结构变化需重导，运行时检测与清单不一致则停止提示；单纯密钥更新下轮生效，不把秘密写入清单。

## 7. 通知：两个正交维度

### 7.1 成功/失败

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| notify.on_success | true | 发送成功，包括已签到/状态跳过，但必须注明非本次新签到 |
| notify.on_failure | true | 发送失败、部分失败、任务超时等结果 |
| notify.delivery | individual | individual 分别；grouped 集合 |
| notify.channel | auto | 青龙独立配置钉钉/飞书，旧通知策略和格式不变 |

任务所有账号成功/已签到/本服务日跳过为成功类；任一失败为任务失败，同时保留部分成功计数。
四种开关组合全部支持；都关闭时不发业务通知，但保留结果/日志/独立监控。
通知开启但无可用渠道预检报错，避免误以为已经收到保护。

### 7.2 分别通知（默认推荐）

每个逻辑任务结束立即发一条，里面列该任务所有账号结果，不等待其他任务。
任务执行时间/耗时不同优先选择此模式。“分别”首版是每任务，不是原 CLI 的每账号 individual。

### 7.3 集合通知

- 按具体时区 + 规范化 cron + 有效通知渠道/策略分组，导入为一个批次任务。
- 同组逐个隔离执行，单项失败不阻断其余，结束后发一份报告。
- 00:30 不等 08:30；不同 cron 的任务分别成组，偶然同分钟也不跨进程拼接。
- 不同通知覆盖自动拆组；任务上限默认 900 秒，组整体上限 1800 秒，可配置并校验。
- 组超时明确列已完成/失败/未执行项，不能把缺失结果当成功。
- 集合模式会延迟到本组结束；需要失败立刻告警时选分别，首版不额外发送重复失败消息。
- 过滤按逻辑任务，而非只看组结论：仅失败列失败任务，仅成功列成功任务，保留总体计数并注明筛选。
- 全部被过滤不发送，但仍落盘/上报执行结果；无需跨天收集器或通知守护进程。
- 改 delivery/cron 后重新导入，重新组织受管任务，避免同时保留旧组和新组。

### 7.4 内容和投递

必备：来源青龙、整体结论、任务名、计划/实际时间与偏移时区、耗时、成功/已签到/跳过/失败计数、
账号别名、必要任务结果、失败原因与操作建议、运行编号。
积分增量/余额/连续天数仅在获取并确认时展示，不推算；超长按渠道限制分页并保留失败信息与 run_id。

共享传输可复用，青龙报告和格式独立；如需结构化结果字段，增量可选并保留原格式回归测试。
业务结果与投递结果分开记录。投递失败让青龙执行非零，但不回滚签到成功状态。
有限超时/重试，不无限等待；响应不确定可能重复，以 run_id 识别，不承诺恰好一次。
可解析配置且渠道可用时发送配置/运行失败消息；解释器缺失/配置语法错误无法保证发送，外部监控兜底。

## 8. 运行状态和漏执行监控

- 独立青龙 schema，以稳定任务/账号 ID 及站点服务日记录，不读/写原 state v2。
- 服务日跨界时结果不落错日期；原子替换写入，损坏/权限错误明确报错，不静默清空。
- 不同任务可并行，同任务 OS 文件锁；导入器保证一个任务只属于一个受管调度入口。
- 同账号人为配置为不同 ID 不承诺识别去重；能确认的重复配置提示，不存原始 Cookie 作为键。
- 锁占用码 3，不签到、不伪造心跳成功；其余 0/1/2 含义保留。组超时未运行项反映为失败/未执行。
- 记录计划/开始/结束、服务日、版本/revision、计数、退出码、投递状态；被杀/断电不保证完整收尾。
- 可选 Healthchecks 心跳按每个实际导入入口配置，分别按任务、集合按组；不同 cron/来源不共用 URL。
- 开始 /start、成功基础地址、失败 /fail；有限超时、HTTPS、禁重定向、路径 token 脱敏、不带站点 Cookie。
- 心跳故障不阻止签到，不覆盖业务退出码；未配置不额外联网。
- 预览输出每入口 cron/时区/建议宽限期，外部监控由用户同步配置，不由导入器擅自更改。
- 单任务默认可设 30 分钟宽限，组默认可设 45 分钟；须大于执行上限和延迟。
- 同机青龙与监控一起停止不能告警，使用独立服务/主机；关闭任务失败通知不等于关闭漏执行监控。

## 9. 必要日志与自动清理

默认日志保留 14 天，单文件 5 MiB 滚动、目录 100 MiB；
结果记录保留 30 天、目录 20 MiB。集中配置可修改。
每次运行轻量清理，导入器同时创建当地 03:15 的受管维护任务。

- 只清理自有 runtime/logs、runtime/records 中匹配命名/schema 的已完成文件。
- 日期与容量双约束，优先删除最旧已完成文件；活动文件保留并滚动，避免单次大量日志无限增长。
- 不删 state/锁/配置/导入清单/手动备份/其他任务，不调用全局 ql rmlog 代替项目清理。
- 规范化边界，拒绝外部符号链接；写入/清理协调加锁，权限/磁盘故障可见。
- 清理失败记告警但不改写签到结果；必要结果落盘失败则运行失败。
- 维护任务仅失败通知，正常清理不刷屏，记录删除数量/空间；cleanup --dry-run 可预览。
- stdout 与文件出口之前脱敏；禁完整配置、原始页面、Cookie/用户名/密钥 URL 落盘。
- 青龙面板捕获的日志由青龙自己的保留策略管理；本项目不自动改影响他人的全局设置。
- 清理删除不可恢复，需长期存档由用户另行导出；手册明确说明。

## 12. 文档、升级和非目标

正式教程必须覆盖安装、完整模板、文件/秘密引用、一次性授权、一键导入及启用、时间覆盖、
两维通知和结果示例、日志保留与清理、漏执行监控、增删任务/账号、升级/回滚/卸载、排障和脱敏反馈。
保留原 README Actions/CLI 入口，只增加青龙导航，旧链接不破坏。

升级暂停本项目任务、等执行结束，备份 revision/配置/runtime；明确版本更新、重装、检查、同步清单后恢复。
回滚恢复匹配版本/schema/清单，不覆盖其他任务。青龙卸载不影响 Actions；不把关掉 Actions 当作必做步骤。

非目标：跨端同步/主备、自动刷新 Cookie、绕过验证、无限通知重试、自动改青龙全局设置、未经实测的全版本兼容承诺。
