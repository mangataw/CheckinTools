# 自动化与开发说明

## 定时运行

GitHub Actions 默认每天触发两次：北京时间 09:00 和 14:00，不添加应用层随机延迟。
GitHub 的计划任务本身仍可能因平台负载延迟，因此实际开始时间不是严格的准点保证。

## 每日状态去重

定时任务通过 GitHub Actions Cache 保存当日匿名账号状态：

- 成功和今日已签到会记录为当日终态。
- 第二次运行会跳过已有成功终态的账号。
- 失败不会记录为终态，因此第二次运行仍会重试。
- 手动触发不读取定时状态，便于单站点排障。

状态文件只包含站点名和 `account-1` 等匿名编号，不包含 Cookie、用户名或通知凭据。

## HTTP 与日志安全

- 基础地址必须是无账号信息、查询参数和额外路径的 HTTPS URL。
- 携带 Cookie 的跨主机或降级到 HTTP 的重定向会被阻止。
- 日志只使用匿名账号编号，并对已知凭据及敏感赋值进行遮罩。
- CI 不加载真实签到或通知 Secrets。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 所有已配置任务成功或今日已签到 |
| `1` | 至少一个签到或已配置通知失败 |
| `2` | 配置无效、请求的渠道未配置或没有可运行站点 |

## 开发验证

```bash
python -m ruff check .
python -m pytest --cov=checkin_tools --cov-report=term-missing
```

测试使用模拟 HTTP 和脱敏 HTML fixture，不使用真实账号或 Cookie。新增站点应实现统一
`Checker` 接口，并沿用严格配置、匿名日志、安全 HTTP 和故障隔离约束。
